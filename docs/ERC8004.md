# ERC-8004 integration

AgentClear writes transaction-backed provider feedback only after a job has reached a matching terminal settlement outcome. Registry addresses are configuration, not application constants.

## Verified interface and deployments

The implementation was checked on 2026-08-23 against the current official [`erc-8004-contracts` ABI](https://github.com/erc-8004/erc-8004-contracts/blob/main/abis/ReputationRegistry.json) and the repository's [0G deployment change](https://github.com/erc-8004/erc-8004-contracts/pull/83).

The published deployments in that source are:

| Network | Chain ID | IdentityRegistry | ReputationRegistry |
| --- | ---: | --- | --- |
| 0G Mainnet | 16661 | `0x8004A169FB4a3325136EB29fA0ceB6D2e539a432` | `0x8004BAa17C55a88189AE136b182e5fdA19dE9b63` |
| 0G Galileo Testnet | 16602 | `0x8004A818BFB912233c491871b3d84c89A494BD9e` | `0x8004B663056A597Dffe9eCcC1965A193B7388713` |

Operators must independently re-check the current official deployment source before configuring a production release because ERC-8004 remains an evolving standard. AgentClear does not assume a ValidationRegistry deployment.

## Configuration

Set both variables alongside the complete chain signer group:

```dotenv
ERC8004_IDENTITY_REGISTRY_ADDRESS=
ERC8004_REPUTATION_REGISTRY_ADDRESS=
```

Config validation rejects a partial registry pair or registries without the complete signer configuration. `/ready` checks both bytecodes and verifies that `ReputationRegistry.getIdentityRegistry()` returns the configured identity registry.

## Feedback policy

AgentClear calls the current interface:

```solidity
giveFeedback(
  uint256 agentId,
  int128 value,
  uint8 valueDecimals,
  string tag1,
  string tag2,
  string endpoint,
  string feedbackURI,
  bytes32 feedbackHash
)
```

The application derives, rather than accepts, these values:

- paid PASS: `value = 100`, `valueDecimals = 0`
- refunded FAIL: `value = 0`, `valueDecimals = 0`
- `tag1 = agentclear.outcome`
- `tag2 = <deliverable category>`
- `feedbackURI = 0g://<verification-report storage root>`
- `feedbackHash = bytes32(0)` because the URI is content-addressed

Before signing, the gateway resolves the provider token through `ownerOf`, rejects self-feedback, and simulates the call. It then persists the exact signed transaction before broadcast. Confirmation requires a successful receipt, a matching `NewFeedback` event, and a matching non-revoked `readFeedback` result.

## Verification status

The gateway and complete PASS/FAIL REST workflows are exercised against ephemeral Anvil using test-only registries that implement the exact methods/events consumed by the adapter. This proves ABI compatibility and AgentClear orchestration locally. No live 0G ERC-8004 feedback transaction has yet been sent from this repository, so the addresses above are documented configuration candidates—not a claim that AgentClear has written to them.
